# Vidya Academy Content Manager 1.9.31

This plugin manages website copy, page images, videos, and blog metadata in WordPress while the React website keeps its current visual design. Updating from an earlier version preserves saved content and blog posts. Blank image fields use the matching local photo bundled in the React project's `public` folder; known older Unsplash/iStock photo URLs in saved page content are converted to the mapped local school photos. Newly selected WordPress Media Library images or hosted URLs replace those defaults. Same-site HTTP media URLs are upgraded to HTTPS when WordPress is served securely, preventing browsers from blocking uploaded images as mixed content. The floating back-to-top mascot uses only the transparent Vidya uniform animation in `mascot-doll1.webm`.

## Install or update

Upload `Vidya-Academy-CMS-1.9.31.zip` in **WordPress Admin → Plugins → Add New Plugin → Upload Plugin** and activate it. This installer omits duplicate photos and video already shipped with the React site, keeping the ZIP small enough for typical WordPress upload limits. If WordPress cannot replace the installed copy, upload the extracted plugin folder to `wp-content/plugins/vidya-academy-cms/` through your host’s file manager or SFTP. The content and blog posts are stored in the WordPress database. The Mandatory Disclosure tab includes the screenshot-based tables; use **Upload / choose PDF** in each document row to add its official PDF from the WordPress Media Library. The site displays a “PDF not uploaded yet” status until a file is selected.

## Edit content and media

Open **Vidya Content** in the WordPress sidebar for shared site content. Use the separate **Events**, **Achievements**, **Blogs**, **FAQs**, and **SEO Landing Pages** menus for those collections. Only fields labeled **Desktop hero image** have a second, optional **Mobile hero image** field. Every other photo uses one upload for desktop, tablet, and phone. The editor shows the size beside each image field; the full list is in `IMAGE-SIZES.txt`. Event, achievement, and blog editors let you change each story’s cover heading and caption, gallery heading, and heading and caption for each gallery photo. Article text remains editable with the WordPress rich text/HTML editor. SEO page content can be edited as structured sections or pasted as HTML.

Campus now presents its existing grounds and building photos together under **Infrastructure** without the old photo marquees. The **Our Upcoming Campus** group edits the two facility lists and their description in WordPress; it is presented as text and does not use the supplied planning infographic as a page image.

The homepage admission cards show Play Group–Nursery, LKG–UKG, Classes 1–5, and Classes 6–8. The in-site **Mandatory Disclosure** page is editable from its own tab. The plugin includes the school facts and disclosure rows from the supplied screenshots. Add each PDF’s official URL to its matching row before publishing the links.

SEO Landing Pages let a developer set a meta title and description, paste complete body HTML, and add page CSS. Use **Upload / insert image into HTML** to select Media Library images and insert their `<img>` markup at the cursor; the hero image also has an upload field. CSS selectors are scoped to that landing page, and WordPress removes unsafe HTML such as scripts. The React navigation and footer remain the site shell. Pages are fetched from `/wp-json/vidya/v1/seo-pages/{slug}` and rendered at `/schools/{slug}`. About page Hero has exactly two editable photos: the main image (desktop and optional mobile crop) and the inset image.

The homepage hero has a desktop video URL and optional phone video URL, poster images, and intro logo image. Default photos, logos, mascot art, and the 39-second, 1600 × 900 homepage video are served from the React project's `public` folder. The plugin returns their relative paths so React serves them from its own domain; it no longer carries duplicate copies that inflate the WordPress upload. Images and videos chosen in WordPress remain preserved. The footer back-to-top mascot uses a transparent VP9 WebM video only; upload a short looping portrait video (484 × 736 px or 600 × 900 px, 24–30 fps, ideally under 2 MB). No separate mascot poster image is used. FAQ and learning-card mascot images should be transparent PNG/WebP at 600 × 720 px (optional phone crop: 360 × 500 px); the admissions mascot image should be 900 × 1100 px. Change the homepage video in **Home → Hero → Hero background video**.

The **Blogs Page Text** section controls the blog listing heading and empty state, and now includes optional custom page HTML/CSS and meta title/description fields. Individual published posts are managed from **Blogs** and appear newest first. Each post accepts a search meta title/description plus optional custom article HTML/CSS, alongside the standard rich-text editor. Custom CSS is scoped to its page or article so it cannot affect the React navigation or footer. The React blog list uses a responsive three-column desktop grid; blog detail pages use a full-width image hero. Events, Achievements, and FAQs each have separate add/edit controls, statuses, and media fields.

## API and permissions

The frontend reads `/wp-json/vidya/v1/content`, `/wp-json/vidya/v1/blogs`, and individual SEO pages from `/wp-json/vidya/v1/seo-pages/{slug}`. Blog saving, image selection, and content updates require an administrator login and nonce. Public content endpoints are read-only. Enquiry submissions use the existing validated `/wp-json/vidya/v1/enquiry` route. Set `VITE_WORDPRESS_URL` in the frontend environment and allow the frontend origin in CORS if your server blocks it.
